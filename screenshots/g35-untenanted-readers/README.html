G35 — a coach's business sees none of the platform's shared content

Two screens, each captured twice in the real running app on the real route: once for a coach's business, "Trailhead Strength & Conditioning", and once for the platform's own business, "Primary". The platform shot in each pair is the comparison. Without it, "nothing is shown" would look the same as a page that failed to load. Annotations are burned into each PNG. Captured 2026-09-26 on the dev database by scripts/capture-g35-untenanted-screenshots.mjs.

What these shots are, and are not

  • Light only. The admin screens have no working dark mode, and the draft preview is an admin screen. The two chat shots are light as well, so each pair compares like with like.
  • How the coach's web address was reached. Every public request carried x-forwarded-host: phase4-coach.test, a web address the dev database assigns to Trailhead. This is the header the app reads first to decide which business a visitor is on, and it is the one the hosting provider sets in production. The platform shots sent www.darrenjpaul.com the same way. Opening http://phase4-coach.test:3064 directly was tried first and does not work locally. The site's security settings upgrade every script on a non-local http address to https, so the page never becomes interactive and the chat cannot answer.
  • What was written to the dev database, and what was removed. The two draft pages behind shots 3 and 4 were created by the script, one for each business, holding the same document. No page on the dev database had a questions section set to "Live", so there was nothing existing to photograph. Both drafts were deleted when the script finished, and a re-read confirmed it (query below). The chat questions are real visits, so the app kept its own record of each conversation, as it does for any visitor. The shots are from conversations ff8f9ab3-427c-4873-b165-022b73b8d865 (coach) and 15d2026d-5525-4ff6-b0ef-99b21774d1ef (platform). One earlier take left two more, 4b451268… and 48c76044…. None was handed to a person, and no email could have been sent, because no business on the dev database has a reply-to address.
  • The top bar still shows the platform's logo on the coach's web address. It is the site's shared frame, and it is the same on every web address today. Giving each coach their own name there is separate work, not part of G35. Shot 1 says so on the image.
  • Two things visible in the chat shots are not G35, and were not fixed here:
    • The platform's answer (shot 2) says the client stories are "on the cards beside this reply". The chat has no card for client stories. It can show programmes, events, consultation links, free times and a contact form, and nothing else. So that sentence describes the screen wrongly.
    • The coach's answer (shot 1) calls the consultation "free". No lookup told it that, and the assistant's instructions forbid saying so unless one does. Nothing caught it before the visitor saw it. It also offers to check this week's times, but this coach has no calendar connected, so the only thing it can offer is the contact page already on screen.
  • Not captured: a live testimonials section on a page. It follows the same rule as the questions section, with its own words ("uses live testimonials … Switch it to your own quotes"). The tests in __tests__/lib/funnels/sections/resolve.test.ts and __tests__/components/funnels/live-feed-islands-tenant.test.tsx cover it. Capturing it would have needed two more drafts for the same picture.

Quizzes as cards — what was verified

Every frame is the real app on its real route, driven by scripts/capture-quizzes-as-cards.ts. The callouts are burned into each PNG.

Measured on the dev copy (anjvztjiokcgiyhobknq), asserted in the DOM before each shot:

  • No table. page.locator("table").count() === 0, and two [data-testid="quiz-card"] elements present. Checked first, because a table with rounded corners photographs like a card at thumbnail size.
  • The preview follows the funnels board's rule. The seeded quiz sits on a published page and frames /go/athlete-quiz?preview=1; the quiz created during the run sits on an unpublished page and frames /preview/quiz-card-check-394730. Both read out of the iframe's src.
  • The badge is the quiz's status, not the funnel's. active on the seeded quiz, draft on the new one — whose funnel is also a draft, so only a correct implementation distinguishes them.
  • Both buttons were followed, not just read. Open reaches the question editor; the button beside it reaches the page builder for the step the quiz sits on. Neither landed on a 404.
  • The second quiz was made through the real New funnel dialog — template Run a quiz — and deleted again at the end of the run. A hand-written row would prove nothing about the screen an owner gets.

Two things these shots show that are NOT this change:

  • The new quiz carries Unverified scoring because createQuizFrom copies seed_marker from whatever it clones, and the default source is the reconstructed blueprint. Pre-existing, and arguably right — a clone of unverified weights is still unverified.
  • The draft card's thumbnail shows the preview's own strip, "This page previews, but publishing will refuse it — the quiz is draft, not active." That is the publish gate reporting itself correctly, and it is why a draft quiz still draws in a preview at all.

Not photographed: a quiz on no page (the No preview yet state) and the failed-read state. Both are covered by unit tests; producing either on screen would have meant writing to the database rather than using the product.

One board, two screens — what was verified

Both frames are the real app on its real route, driven by scripts/capture-one-board.ts. The callouts are burned into each PNG.

Asserted in the DOM before each shot, on the dev copy (anjvztjiokcgiyhobknq):

  • One card, both screens. /admin/pages renders [data-testid="funnel-card"] — the funnels board's own card. That is the change.
  • The goal badge is page-only. Present on the landing page card, and getByText("Capture leads").count() === 0 on the funnels board. Asserted in both directions across the two shots, because an absence proves nothing without the presence.
  • The ⚙ settings link is funnel-only. Neither a[href="/admin/pages/<id>"] nor a[href="/admin/funnels/<id>"] appears on a landing page card; a funnel card has one.
  • The sidebar tab stays right. A page card's Open must start /admin/pages/<id>/edit/. Both routes serve a page — the funnels one redirects — so a wrong link works and merely lights the wrong tab. That is the defect adminFunnelBase exists to prevent, and the one this merge nearly reintroduced.
  • Each screen keeps its own words. "Search pages…" / "Search funnels and pages…", "New landing page" / "New funnel".
  • The landing page in shot 1 was made through the real dialog and deleted at the end of the run. The dev copy's own page carries goal: null and so cannot show the badge — asserting against data that cannot answer would have proved nothing.

Two bugs the merge exposed, both found by retargeting the deleted board's tests rather than deleting them:

  • FunnelCard hardcoded /admin/funnels/<id>/edit/<step>. Invisible until the pages board rendered this card.
  • FunnelList's delete said "Funnel deleted." and asked about "all of its pages". A landing page IS a funnels row, so it goes through the same endpoint, and a message written from the endpoint names a thing the owner has never seen. This had already shipped once and been fixed on the old board; the fix now lives where it survives the board being replaced.

Not changed, on purpose: there is no migration. funnels.kind stays. The model — one table, one shape, one renderer, one flag — was already sound; the confusion was two components that drifted.

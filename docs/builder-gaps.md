# Page builder — tracked gap inventory

Every row's `Constrained at` cites a real `file:line`, opened and confirmed against this
worktree at branch point `b3544283` (2026-09-13). This doc is re-read by Task 12, which ticks
rows off — do not renumber IDs once a later task references one.

`Status` is one of `open` / `closing in 2026-09-13 build` / `closed`.

## Design gaps

These are all things the *2026-09-13 build* (this branch) is closing. They exist because
`prompt.ts`'s stylesheet-decides-everything model was correct when the engine shipped and has
since been paid for long enough to see the cost: the model is handed a design surface small
enough that most pages come out looking the same.

## Capability gaps

These are explicitly **not** part of the 2026-09-13 build (see spec §9). Logged here so the
owner can see the whole shape of what the builder can't do yet, not just the slice this build
closes.

| ID | Area | What the owner cannot do | Constrained at | Severity | Status |

| C2 | Section kinds | Add a `gallery`, logo-strip, comparison-table, countdown, guarantee-badge, contact/map or before-after section — `SECTION_KINDS` lists 11 kinds and none of these are among them | `lib/funnels/sections/registry.ts:185` | Medium | open |
| C3 | Input | Paste a reference design or brand board image into chat. **Closed 2026-09-14 (Phase 1 of "give the builder's AI eyes").** `ChatPane.tsx` now has a paste handler and a file picker; the image is downscaled to 1568px on the long edge IN THE BROWSER (`lib/funnels/reference-image.ts`) because that is what Claude downscales to anyway, then rides in the AI SDK **user message** via `callAgent`/`streamAgent`'s new `images` option (`lib/ai/anthropic.ts`) — never the system prompt, which is a cached prefix. It is **never stored**: not in `funnel_step_turns`, not in Firebase Storage, not in the document, not in a log; a test asserts the base64 reaches no argument of `appendTurn`. The pictures go to **one critic, not the builder model**: the art director alone, via `CriticLens.seesRender` on the lens table in `lib/funnels/sections/review/critics.ts`, whose brief was rewritten to lead with what only a render shows (empty regions, unreadable text, ragged wrapping, dead space, overflow); the copywriter and conversion-strategist lenses never see it. It runs only on turns that already earn a review — a first draft's `set_page` and the Polish button, both through the shared `runReviewStage` — so an ordinary edit turn renders nothing and pays nothing. The picture is **never stored**: not in `funnel_step_turns`, not Firebase Storage, not the document, not a log; it exists as base64 in memory for the one `callAgent` call and is garbage after. **The island placeholder is the load-bearing part of this row.** A static render cannot execute React, so every interactive region is genuinely blank in the screenshot — `renderIsland()` in `lib/funnels/sections/render.ts` emits an empty `<div data-djp-island>` that only a real browser hydrates, and the form section hits it UNCONDITIONALLY, alongside live testimonials, live FAQ, checkout/event/booking CTAs and the quiz. The art director filed those blanks as high-severity empty bands, and on a real page the reviser acted on one: it proposed replacing a working live testimonial feed (a real Wayde van Niekerk quote) with a fabricated quote attributed to an invented person under a real coach's page. Telling the critic in prose that those regions are live (`RenderedPage.dynamicRegions` plus a `renderNote()` instruction) was tried first and **measured insufficient against a real model** — the fabrication stopped but the false empty-band finding did not. The fix instead changes what the picture shows, not what the critic is told: `buildRenderDocument` (`lib/funnels/render-image.ts`) injects a render-only stylesheet that paints every island as a dashed, labelled placeholder box naming what fills it live, so there is no blank left to report. Anyone touching this later needs to know the prompt-only fix does not work. **Still out of scope, deliberately:** mobile/multi-viewport rendering (desktop only); the builder model seeing the page on ordinary edit turns; the reviser seeing the render at all (it acts on findings, never pictures); storing the render in any form; rendering as a publish gate. Typeface fidelity is approximate by design, not a bug — three of the five font pairings (`bold`, `editorial`, `athletic`) resolve to system faces that render differently per OS, so there is no single "correct" render to chase, and the critic is explicitly told never to file a finding about which typeface was used. **Honestly: this has never run on Vercel.** The Vercel CLI and MCP connector both 403 on this account's scope from this environment, so the production deploy of `puppeteer-core` + `@sparticuz/chromium` (added to `serverExternalPackages` in `next.config.mjs`) is unverified — the feature fails soft at runtime if Chromium cannot launch, but a bundling failure at build time would make it a silent, permanent no-op with no alarm raised.
